Overview

One toolkit, every phase of the migration

Rather than hand-rolling every step, the toolkit leans on Google-provided services — BigQuery Migration Service SQL translation, BigQuery Data Transfer Service, and Storage Transfer Service — and wraps them in idempotent, retry-safe Python with structured logging and a single CLI.

Architecture
  • src/cli.py — click entry point
  • src/migrator.py — config + wave orchestration
  • Per-module clients for SF, BQ, GCS, DTS
Safety
  • Idempotent — safe to re-run any phase
  • State persisted to migration_state.json
  • Validation gate blocks cutover on failure
Observability
  • Structured logging via structlog/logging
  • Markdown reports per phase
  • Per-table progress tracking
Get started

Quick Start

Install dependencies, set credentials via environment variables, then drive the whole migration through one CLI.

1

Install & configure

bash
pip install -r requirements.txt

export SNOWFLAKE_ACCOUNT=myaccount
export SNOWFLAKE_USER=myuser
export SNOWFLAKE_PASSWORD=mypassword
export GCP_PROJECT_ID=my-gcp-project
export GCS_STAGING_BUCKET=my-migration-bucket
2

Edit config/migration_config.yaml

yaml
tables:
  - sf_table: analytics.public.users
    bq_table: users
    key_col: user_id
    watermark_col: updated_at
    wave: 1
3

Run the lifecycle

bash
python -m src.cli assess
python -m src.cli translate-sql
python -m src.cli create-schema
python -m src.cli transfer
python -m src.cli sync
python -m src.cli validate
python -m src.cli cutover

Module Documentation

Every module under src/ has a single responsibility and is importable without side effects. Click a card or use the sidebar to jump to its full reference.

Phase 1 · Assess

src/assessment.py

Inventories Snowflake databases, schemas, tables, views, stored procedures, UDFs, tasks, and streams. Estimates row counts and complexity, then groups objects into a dependency- and size-aware migration wave plan.

Key classes / functions
  • SnowflakeAssessor.discover_tables()
  • SnowflakeAssessor.discover_views()
  • SnowflakeAssessor.discover_routines()
  • SnowflakeAssessor.discover_tasks_and_streams()
  • SnowflakeAssessor.build_wave_plan()
  • SnowflakeAssessor.generate_report()
Inputs / Outputs
  • In: Snowflake connection params, database/schema names
  • Out: ObjectInventory list, MigrationWave plan
  • Out: Markdown + JSON assessment report
python
assessor = SnowflakeAssessor(sf_conn_params={...})
assessor.discover_tables(database="ANALYTICS")
assessor.discover_views(database="ANALYTICS")
plan = assessor.build_wave_plan(max_waves=5)
print(assessor.generate_report(plan))

Phase 2 · Translate SQL

src/sql_translator.py

Batch-translates Snowflake views, stored procedures, UDFs, and queries to BigQuery SQL using Google's BigQuery Migration Service literal-translation API (google.cloud.bigquery_migration_v2). Retries on rate limits with exponential backoff and continues past per-object failures.

Key classes / functions
  • SnowflakeSqlTranslator.translate_batch()
  • SnowflakeSqlTranslator._translate_one() — submits a MigrationTask
  • SnowflakeSqlTranslator.generate_issues_report()
Inputs / Outputs
  • In: TranslationUnit (name, type, source SQL)
  • Out: TranslationResult with translated SQL + untranslated tokens
  • Out: Markdown translation issues report
python
translator = SnowflakeSqlTranslator(project_id="my-gcp-project")
units = [TranslationUnit("vw_active_users", "view", "SELECT id FROM users")]
results = translator.translate_batch(units)
print(translator.generate_issues_report(results))

Phase 3 · Create Schema

src/schema_translator.py

Maps Snowflake DDL types to BigQuery equivalents and creates target tables, with auto-detected clustering and partitioning. Delegates view/procedure/UDF DDL bodies to sql_translator.SnowflakeSqlTranslator for SQL-level translation.

Key classes / functions
  • translate_type() — NUMBER/VARIANT/TIMESTAMP_NTZ mapping
  • fetch_snowflake_columns()
  • detect_clustering() — reads Snowflake cluster keys
  • translate_view_ddl() / translate_routine_ddl()
  • create_bq_table() / translate_and_create()
Inputs / Outputs
  • In: Snowflake column metadata, fully-qualified table name
  • Out: bigquery.Table created in target dataset
  • Out: JSON schema export for review
python
translator = SnowflakeToBigQueryTranslator(
    project_id="my-gcp-project", dataset_id="migrated_dataset",
    sf_conn_params={...},
)
cols = translator.fetch_snowflake_columns("analytics.public.users")
cluster_cols = translator.detect_clustering("analytics.public.users")
translator.translate_and_create(cols, table_name="users", cluster_cols=cluster_cols)

Phase 4 · Transfer Data

src/data_transfer.py

Bulk-loads Snowflake tables into BigQuery via GCS staging (export → load job), and configures BigQuery Data Transfer Service for recurring, scheduled syncs. Retries with backoff and tracks per-table progress for resumability.

Key classes / functions
  • export_table_to_gcs() — Snowflake COPY INTO
  • load_gcs_to_bq() — BQ load job
  • backfill_table() / backfill_all()
  • create_dts_transfer_config()
Inputs / Outputs
  • In: source/target table pairs, GCS bucket
  • Out: TransferProgress per table
  • Out: Markdown progress report
python
orchestrator = DataTransferOrchestrator(
    sf_conn_params={...}, gcp_project="my-gcp-project",
    gcs_bucket="my-migration-bucket", bq_dataset="migrated_dataset",
)
orchestrator.backfill_all([{"sf_table": "analytics.public.users", "bq_table": "users"}])
print(orchestrator.progress_report())

Phase 5 · Incremental Sync

src/incremental_sync.py

CDC/watermark-based sync that MERGEs Snowflake changes into BigQuery. Prefers a Snowflake STREAM, falls back to an updated_at watermark, and falls back again to a full reload with a warning when neither is available.

Key classes / functions
  • sync_table() — strategy dispatcher
  • sync_via_watermark() / sync_via_stream()
  • full_reload() — fallback strategy
  • _merge_rows_into_bq() — idempotent MERGE
Inputs / Outputs
  • In: key column, optional watermark column or stream name
  • Out: SyncResult (strategy, rows synced, watermark)
python
syncer = IncrementalSyncer(sf_conn_params={...}, bq_project="my-gcp-project", bq_dataset="migrated_dataset")
result = syncer.sync_table(
    sf_table="analytics.public.orders", bq_table="orders",
    key_col="order_id", watermark_col="updated_at",
)

Phase 6 · Validate

src/data_validator.py

Row count, MD5 checksum, null-count, and column-type parity checks between Snowflake and BigQuery. Automatically switches to sampling-based checksums above a configurable row threshold for very large tables.

Key classes / functions
  • validate_table() / validate_all_tables()
  • get_sampled_checksum() — large-table sampling
  • check_column_types()
  • generate_report() / generate_summary_dashboard()
Inputs / Outputs
  • In: table pairs + key column
  • Out: ValidationResult per table
  • Out: Markdown report + summary dashboard
python
validator = MigrationValidator(sf_conn_params={...}, bq_project="my-gcp-project", bq_dataset="migrated_dataset")
results = validator.validate_all_tables([{"sf_table": "analytics.public.users", "bq_table": "users", "key_col": "user_id"}])
print(validator.generate_summary_dashboard(results))

Phase 7 · Cutover

src/cutover_manager.py

Orchestrates the dual-write cutover window, gates the final switch to BigQuery behind a validation callback, and supports rollback to Snowflake at any phase. Status is persisted to migration_state.json and rendered as a runbook.

Key classes / functions
  • start_dual_write() — idempotent phase entry
  • run_validation_gate()
  • switch_to_bigquery() — refuses without a pass
  • rollback() / generate_runbook()
Inputs / Outputs
  • In: table name, validation callback
  • Out: CutoverStatus (phase, timestamps, notes)
  • Out: Markdown cutover runbook
python
manager = CutoverManager(state_path="migration_state.json")
status = manager.cutover_table("users", validate_fn=lambda t: validator.validate_table(...).passed)
print(manager.generate_runbook())

Orchestration

src/migrator.py

Loads config/migration_config.yaml, resolves secrets from environment variables, and drives per-wave execution with state persisted to migration_state.json — so any phase can be safely re-run without redoing completed tables.

Key classes / functions
  • load_config()
  • MigrationState.mark_complete() / .is_complete()
  • Migrator.run_phase_for_wave()
Inputs / Outputs
  • In: migration_config.yaml path
  • Out: MigrationConfig, wave-grouped TableConfig list

Configuration

Every connection parameter is resolved from an environment variable name declared in YAML — no secrets ever live in the config file itself.

config/migration_config.yaml
snowflake:
  account_env: SNOWFLAKE_ACCOUNT
  user_env: SNOWFLAKE_USER
  password_env: SNOWFLAKE_PASSWORD
  database: ANALYTICS
bigquery:
  project_id_env: GCP_PROJECT_ID
  dataset: migrated_dataset
tables:
  - sf_table: analytics.public.users
    bq_table: users
    key_col: user_id
    watermark_col: updated_at
    wave: 1
